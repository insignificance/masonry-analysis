🏭 工厂方法模式 (Factory Method)

模式定义

意图：定义一个创建对象的接口，让子类决定实例化哪个类

在 Masonry 中的应用

1. MASConstraintMaker 作为工厂

classDiagram class MASConstraintMaker { +MASConstraint* left +MASConstraint* top +MASConstraint* width +MASConstraint* edges +MASConstraint* size +MASConstraint* center } class MASConstraint { } %% MASConstraint 是抽象类 class MASViewConstraint { +initWithFirstViewAttribute() } class MASCompositeConstraint { +initWithChildren() } MASConstraintMaker --> MASConstraint : creates MASConstraint <|-- MASViewConstraint MASConstraint <|-- MASCompositeConstraint

2. 具体实现代码

// MASConstraintMaker.m

// 工厂方法：创建单约束
- (MASConstraint *)addConstraintWithLayoutAttribute:(NSLayoutAttribute)layoutAttribute {
    MASViewAttribute *viewAttribute = [[MASViewAttribute alloc] initWithView:self.view
                                                             layoutAttribute:layoutAttribute];
    MASViewConstraint *newConstraint = [[MASViewConstraint alloc] initWithFirstViewAttribute:viewAttribute];
    newConstraint.delegate = self;
    [self.constraints addObject:newConstraint];
    return newConstraint;
}

// 工厂方法：创建复合约束
- (MASConstraint *)addConstraintWithAttributes:(MASAttribute)attrs {
    NSMutableArray *attributes = [NSMutableArray array];

    // 根据位掩码选择属性
    if (attrs & MASAttributeLeft) [attributes addObject:self.view.mas_left];
    if (attrs & MASAttributeRight) [attributes addObject:self.view.mas_right];
    // ... 其他属性

    // 创建子约束数组
    NSMutableArray *children = [NSMutableArray array];
    for (MASViewAttribute *a in attributes) {
        [children addObject:[[MASViewConstraint alloc] initWithFirstViewAttribute:a]];
    }

    // 创建复合约束
    MASCompositeConstraint *constraint = [[MASCompositeConstraint alloc] initWithChildren:children];
    constraint.delegate = self;
    [self.constraints addObject:constraint];
    return constraint;
}

// 属性访问器（工厂入口）
- (MASConstraint *)left {
    return [self addConstraintWithLayoutAttribute:NSLayoutAttributeLeft];
}

- (MASConstraint *)edges {
    return [self addConstraintWithAttributes:MASAttributeTop | MASAttributeLeft |
                                              MASAttributeRight | MASAttributeBottom];
}

3. 使用示例

MASConstraintMaker *maker = [[MASConstraintMaker alloc] initWithView:view];

// 调用工厂方法，返回不同类型的约束
MASConstraint *c1 = maker.left;           // 返回 MASViewConstraint
MASConstraint *c2 = maker.edges;          // 返回 MASCompositeConstraint
MASConstraint *c3 = maker.width;          // 返回 MASViewConstraint

模式优势

  • ✅ 解耦：客户端不需要知道具体类名
  • ✅ 扩展性：易于添加新的约束类型
  • ✅ 统一接口：所有约束返回相同的抽象类型

🏗️ 建造者模式 (Builder Pattern)

模式定义

意图：将一个复杂对象的构建与它的表示分离，使同样的构建过程可以创建不同的表示

在 Masonry 中的应用

1. 链式API设计

flowchart TD A[make.left] --> B["返回MASViewConstraint"] B --> C[".equalTo(superview)"] C --> D["返回self"] D --> E[".offset(10)"] E --> F["返回self"] F --> G[".priorityHigh()"] G --> H["返回self"] H --> I["链式完成"]

2. 核心实现

// MASConstraint.h
- (MASConstraint * (^)(id))equalTo;
- (MASConstraint * (^)(CGFloat))offset;
- (MASConstraint * (^)(MASLayoutPriority))priority;

// MASConstraint.m
- (MASConstraint * (^)(id))equalTo {
    return ^id(id attribute) {
        // 实现逻辑（子类具体实现）
        return self;  // 关键：返回self实现链式
    };
}

- (MASConstraint * (^)(CGFloat))offset {
    return ^id(CGFloat offset) {
        self.offset = offset;  // 设置值
        return self;           // 返回self继续链式
    };
}

- (MASConstraint * (^)(MASLayoutPriority))priority {
    return ^id(MASLayoutPriority priority) {
        self.priority = priority;
        return self;
    };
}

3. 完整建造过程

// 用户代码
[view mas_makeConstraints:^(MASConstraintMaker *make) {
    make.left.equalTo(superview)
        .offset(10)
        .priorityHigh()
        .key(@"leftConstraint");
}];

// 内部执行流程
// 1. make.left → 创建MASViewConstraint
// 2. .equalTo(superview) → 设置关系，返回self
// 3. .offset(10) → 设置偏移，返回self
// 4. .priorityHigh() → 设置优先级，返回self
// 5. .key(@"key") → 设置key，返回self
// 6. Block结束 → 调用install()

4. 语义化辅助方法

// 提高代码可读性
- (MASConstraint *)with {
    return self;  // 无实际作用，仅增强语义
}

- (MASConstraint *)and {
    return self;  // 无实际作用，仅增强语义
}

// 使用示例
make.left.equalTo(superview).with.offset(10);
make.top.equalTo(superview).and.offset(20);

模式优势

  • ✅ 流畅性：代码读起来像自然语言
  • ✅ 可读性：链式调用逻辑清晰
  • ✅ 灵活性：可以任意组合配置项
  • ✅ 封装性：隐藏内部实现细节

🌳 组合模式 (Composite Pattern)

模式定义

意图：将对象组合成树形结构以表示"部分-整体"的层次结构，使得用户对单个对象和组合对象的使用具有一致性

在 Masonry 中的应用

1. 类结构

classDiagram class MASConstraint { +equalTo() +offset() +install() +uninstall() } %% MASConstraint 是抽象类 class MASViewConstraint { -MASViewAttribute* first -MASViewAttribute* second +install() } class MASCompositeConstraint { -NSArray* children +install() +uninstall() } MASConstraint <|-- MASViewConstraint MASConstraint <|-- MASCompositeConstraint MASCompositeConstraint o-- MASViewConstraint : contains

2. 统一接口

// 抽象基类定义统一接口
@interface MASConstraint : NSObject

// 配置方法（所有子类必须实现）
- (MASConstraint * (^)(id))equalTo;
- (MASConstraint * (^)(CGFloat))offset;
- (MASConstraint * (^)(MASLayoutPriority))priority;

// 操作方法
- (void)install;
- (void)uninstall;

@end

3. 单约束实现

// MASViewConstraint.m
- (void)install {
    // 创建并添加单个NSLayoutConstraint
    NSLayoutConstraint *layoutConstraint = [self createLayoutConstraint];
    [self.firstViewAttribute.view addConstraint:layoutConstraint];
}

4. 复合约束实现

// MASCompositeConstraint.m
- (void)install {
    // 递归调用所有子约束的install
    for (MASConstraint *child in self.children) {
        child.updateExisting = self.updateExisting;
        [child install];
    }
}

- (void)uninstall {
    // 递归卸载所有子约束
    for (MASConstraint *child in self.children) {
        [child uninstall];
    }
}

5. 透明性示例

// 用户无需知道是单约束还是复合约束
MASConstraint *c1 = make.left;      // 单约束
MASConstraint *c2 = make.edges;     // 复合约束

// 使用相同的API
c1.equalTo(superview).offset(10);
c2.equalTo(superview).insets(UIEdgeInsetsMake(10, 10, 10, 10));

// 相同的安装方式
[c1 install];
[c2 install];  // 内部会遍历4个子约束

模式优势

  • ✅ 一致性：单个对象和组合对象使用相同接口
  • ✅ 简化客户端：客户端无需区分类型
  • ✅ 扩展性：易于添加新的组合方式
  • ✅ 递归结构：天然支持树形层次

📡 代理模式 (Proxy Pattern)

模式定义

意图：为其他对象提供一种代理以控制对这个对象的访问

在 Masonry 中的应用

1. 代理协议定义

// MASConstraintDelegate.h
@protocol MASConstraintDelegate 

- (void)constraint:(MASConstraint *)constraint
    shouldBeReplacedWithConstraint:(MASConstraint *)replacementConstraint;

- (MASConstraint *)constraint:(MASConstraint *)constraint
    addConstraintWithLayoutAttribute:(NSLayoutAttribute)layoutAttribute;

@end

2. 代理关系图

flowchart TD A[MASViewConstraint] -->|delegate| B[MASConstraintMaker] C[MASCompositeConstraint] -->|delegate| B B -->|实现协议| D[MASConstraintDelegate] E["用户调用make.left"] --> A A -->|需要组合| B B -->|替换约束| C C -->|包含| A

3. 约束替换逻辑

// MASConstraintMaker.m (代理实现)
- (void)constraint:(MASConstraint *)constraint
    shouldBeReplacedWithConstraint:(MASConstraint *)replacementConstraint {

    NSUInteger index = [self.constraints indexOfObject:constraint];
    NSAssert(index != NSNotFound, @"Could not find constraint %@", constraint);

    // 用复合约束替换单约束
    [self.constraints replaceObjectAtIndex:index withObject:replacementConstraint];
}

// MASConstraintMaker.m (代理实现)
- (MASConstraint *)constraint:(MASConstraint *)constraint
    addConstraintWithLayoutAttribute:(NSLayoutAttribute)layoutAttribute {

    MASViewAttribute *viewAttribute = [[MASViewAttribute alloc]
                                       initWithView:self.view
                                       layoutAttribute:layoutAttribute];
    MASViewConstraint *newConstraint = [[MASViewConstraint alloc]
                                        initWithFirstViewAttribute:viewAttribute];

    if ([constraint isKindOfClass:MASViewConstraint.class]) {
        // 单约束 → 复合约束的升级
        NSArray *children = @[constraint, newConstraint];
        MASCompositeConstraint *compositeConstraint = [[MASCompositeConstraint alloc]
                                                       initWithChildren:children];
        compositeConstraint.delegate = self;

        // 通过代理替换
        [self constraint:constraint shouldBeReplacedWithConstraint:compositeConstraint];
        return compositeConstraint;
    }

    if (!constraint) {
        newConstraint.delegate = self;
        [self.constraints addObject:newConstraint];
    }

    return newConstraint;
}

4. 使用场景

// 场景1：单约束 → 复合约束
MASConstraintMaker *maker = [[MASConstraintMaker alloc] initWithView:view];
MASConstraint *c1 = maker.left;  // 创建单约束

// 后续添加right，自动升级为复合约束
MASConstraint *c2 = c1.right;    // 触发代理，创建复合约束

// 场景2：约束替换
// 内部：c1被替换为composite，c2指向composite

模式优势

  • ✅ 控制访问：管理约束的创建和替换
  • ✅ 解耦：约束无需知道工厂的内部实现
  • ✅ 灵活性：动态改变对象结构
  • ✅ 扩展性：易于添加新的约束类型

🎯 策略模式 (Strategy Pattern)

模式定义

意图：定义一系列算法，将每个算法封装起来，并使它们可以互换

在 Masonry 中的应用

1. 三种创建策略

flowchart TD A["用户选择方法"] --> B{"策略选择"} B -->|makeConstraints| C["添加策略"] B -->|updateConstraints| D["更新策略"] B -->|remakeConstraints| E["重做策略"] C --> F["直接添加"] D --> G["查找并更新"] E --> H["先删除再添加"] F --> I[NSLayoutConstraint] G --> I H --> I

2. 策略实现

// MASConstraintMaker.h
@property (nonatomic, assign) BOOL updateExisting;  // 更新策略标志
@property (nonatomic, assign) BOOL removeExisting;  // 重做策略标志

// View+MASAdditions.m

// 策略1：添加新约束
- (NSArray *)mas_makeConstraints:(void(^)(MASConstraintMaker *))block {
    self.translatesAutoresizingMaskIntoConstraints = NO;
    MASConstraintMaker *constraintMaker = [[MASConstraintMaker alloc] initWithView:self];
    block(constraintMaker);
    return [constraintMaker install];  // 直接安装
}

// 策略2：更新现有约束
- (NSArray *)mas_updateConstraints:(void(^)(MASConstraintMaker *))block {
    self.translatesAutoresizingMaskIntoConstraints = NO;
    MASConstraintMaker *constraintMaker = [[MASConstraintMaker alloc] initWithView:self];
    constraintMaker.updateExisting = YES;  // 设置更新策略
    block(constraintMaker);
    return [constraintMaker install];
}

// 策略3：重做约束
- (NSArray *)mas_remakeConstraints:(void(^)(MASConstraintMaker *))block {
    self.translatesAutoresizingMaskIntoConstraints = NO;
    MASConstraintMaker *constraintMaker = [[MASConstraintMaker alloc] initWithView:self];
    constraintMaker.removeExisting = YES;  // 设置重做策略
    block(constraintMaker);
    return [constraintMaker install];
}

3. 策略执行

// MASConstraintMaker.m
- (NSArray *)install {
    // 策略执行：删除旧约束
    if (self.removeExisting) {
        NSArray *installedConstraints = [MASViewConstraint installedConstraintsForView:self.view];
        for (MASConstraint *constraint in installedConstraints) {
            [constraint uninstall];
        }
    }

    // 复制约束数组
    NSArray *constraints = self.constraints.copy;

    // 策略执行：安装约束
    for (MASConstraint *constraint in constraints) {
        constraint.updateExisting = self.updateExisting;  // 传递策略
        [constraint install];
    }

    [self.constraints removeAllObjects];
    return constraints;
}

// MASViewConstraint.m
- (void)install {
    // 策略执行：更新模式
    if (self.updateExisting) {
        NSArray *installed = [MASViewConstraint installedConstraintsForView:self.firstViewAttribute.view];
        for (MASViewConstraint *constraint in installed) {
            if ([constraint isEqualToConstraint:self]) {
                // 更新现有约束，而非创建新的
                [constraint setLayoutConstraint:self.layoutConstraint];
                return;
            }
        }
    }

    // 默认策略：创建新约束
    self.layoutConstraint = [self createLayoutConstraint];
    [self.firstViewAttribute.view addConstraint:self.layoutConstraint];
}

4. 使用示例

// 动态选择策略
- (void)updateLayout:(BOOL)shouldUpdate {
    if (shouldUpdate) {
        [view mas_updateConstraints:^(MASConstraintMaker *make) {
            // 更新策略：只修改常量值
            make.left.offset(20);
        }];
    } else {
        [view mas_makeConstraints:^(MASConstraintMaker *make) {
            // 添加策略：直接创建新约束
            make.left.offset(20);
        }];
    }
}

// 重置布局
- (void)resetLayout {
    [view mas_remakeConstraints:^(MASConstraintMaker *make) {
        // 重做策略：完全重新定义
        make.edges.equalTo(superview);
    }];
}

模式优势

  • ✅ 算法封装：每种策略独立封装
  • ✅ 灵活切换：运行时选择策略
  • ✅ 易于扩展：添加新策略不影响现有代码
  • ✅ 代码复用：共享约束配置逻辑

🔧 适配器模式 (Adapter Pattern)

模式定义

意图：将一个类的接口转换成客户希望的另一个接口

在 Masonry 中的应用

1. MASViewAttribute 作为适配器

flowchart TD A[UIView/NSView] --> B[MASViewAttribute] C[NSLayoutGuide] --> B D["自定义Item"] --> B B --> E["统一接口"] E --> F[NSLayoutConstraint]

2. 统一不同数据源

// MASViewAttribute.h
@interface MASViewAttribute : NSObject
@property (nonatomic, weak, readonly) MAS_VIEW *view;
@property (nonatomic, weak, readonly) id item;
@property (nonatomic, assign, readonly) NSLayoutAttribute layoutAttribute;
@end

// View+MASAdditions.m
// 适配普通视图
- (MASViewAttribute *)mas_left {
    return [[MASViewAttribute alloc] initWithView:self layoutAttribute:NSLayoutAttributeLeft];
}

// 适配安全区域（iOS 11+）
- (MASViewAttribute *)mas_safeAreaLayoutGuideTop {
    return [[MASViewAttribute alloc] initWithView:self
                                            item:self.safeAreaLayoutGuide
                                 layoutAttribute:NSLayoutAttributeTop];
}

3. 统一处理逻辑

// MASViewConstraint.m
- (NSLayoutConstraint *)createLayoutConstraint {
    // 无论secondViewAttribute来自哪里，处理方式一致
    id firstItem = self.firstViewAttribute.item;
    id secondItem = self.secondViewAttribute.item;

    // 如果secondItem是NSValue（常量），特殊处理
    if ([secondItem isKindOfClass:NSValue.class]) {
        secondItem = nil;
        self.secondViewAttribute = [[MASViewAttribute alloc]
                                    initWithView:nil
                                    item:nil
                                    layoutAttribute:NSLayoutAttributeNotAnAttribute];
    }

    return [NSLayoutConstraint constraintWithItem:firstItem
                                      attribute:self.firstViewAttribute.layoutAttribute
                                      relatedBy:self.layoutRelation
                                         toItem:secondItem
                                      attribute:self.secondViewAttribute.layoutAttribute
                                     multiplier:self.layoutMultiplier
                                       constant:self.layoutConstant];
}

模式优势

  • ✅ 接口统一：不同来源的数据统一处理
  • ✅ 解耦：客户端无需知道具体数据源
  • ✅ 扩展性：易于支持新的数据源类型

🎓 设计模式要点总结

核心模式应用

模式实现类解决的问题关键技巧
工厂方法MASConstraintMaker对象创建属性访问器作为工厂入口
建造者模式MASConstraint复杂配置链式调用返回self
组合模式MASCompositeConstraint树形结构统一接口，递归操作
代理模式MASConstraintDelegate对象替换动态改变对象结构
策略模式MASConstraintMaker属性算法选择位标志控制行为
适配器模式MASViewAttribute接口统一封装不同数据源

设计思想

  1. 开闭原则：对扩展开放，对修改关闭
  2. 单一职责：每个类只做一件事
  3. 依赖倒置：依赖抽象而非具体
  4. 接口隔离：最小接口原则

学习价值

  • ✅ API设计：如何设计流畅的接口
  • ✅ 架构分层：清晰的职责划分
  • ✅ 模式组合：多种模式协同工作
  • ✅ 实用主义：不为了模式而模式
